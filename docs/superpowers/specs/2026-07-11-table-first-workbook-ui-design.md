# RiceFinanceU 工作簿式表格交互设计

## 1. 背景

RiceFinanceU 是一个个人资产快照账本。现有领域模型是清晰的：

- `Asset` 维护长期资产主数据。
- `IncomeRecord` 维护收入事件。
- `Snapshot` 表示一次资产盘点时点。
- `SnapshotValue` 表示某项资产在某次快照中的状态。

当前主要问题不在数据模型，而在交互表达。传统管理系统常把 CRUD 拆成列表、表单、弹窗和详情页，导致低频个人使用仍需要频繁跳转。RiceFinanceU 的数据天然具有行列结构，更适合采用工作簿式表格界面。

本设计以“简约、统一、可审计”为原则：保留大盘作为纯查看界面，其余核心数据通过类似 Excel 的 Sheet 直接维护；所有修改先形成当前 Sheet 草稿，用户显式保存后才写入服务端。

## 2. 产品原则

### 2.1 表格优先，不做通用电子表格

系统采用电子表格的高密度展示、连续编辑和键盘操作，但不支持自由公式、任意列、自定义数据类型或随意改变表结构。

每个 Sheet 都是领域对象的受控投影：

- 系统定义列、数据类型和校验规则。
- 用户直接编辑允许修改的业务单元格。
- 计算字段、系统字段和跨对象派生字段只读。
- 保存动作对应明确的领域操作，而不是单个单元格写入。

### 2.2 界面统一，领域边界不合并

资产主数据和快照状态可以出现在同一行中，但必须通过列权限和保存语义维持边界：

- 资产名称、类型、币种、机构等属于资产主数据。
- 金额、收益和收益率属于快照状态。
- 资产 Sheet 可以展示最新快照状态，但不能直接修改这些状态。
- 所有金额状态变化都通过录入 Sheet 追加快照完成。

### 2.3 显式保存，不做自动保存

第一版只维护当前 Sheet 的内存草稿：

1. 编辑单元格后，该单元格进入未保存状态。
2. 页面显示未保存修改数量。
3. 用户点击当前 Sheet 的保存动作后，系统统一校验并整批提交。
4. 任意关键错误都会阻止整批提交，并定位到具体单元格。
5. 切换 Sheet 时若存在草稿，提示“保存并切换 / 放弃并切换 / 取消”。

第一版不实现自动保存、云端草稿、多个 Sheet 并行草稿、复杂撤销历史或多用户冲突处理。

## 3. 信息架构

主导航采用工作簿标签形式：

```text
大盘（纯 View） | 资产 | 录入 | 收入 | 数据
```

### 3.1 大盘（纯 View）

大盘只负责 Review，不提供数据编辑：

- 总资产和相对上次快照的变化。
- 资产配置和币种分布。
- 投资收益和收益率。
- 收入趋势。
- 定投计划概览。
- 最新快照时间和数据完整性提示。

大盘的所有结果都来自已保存数据，不读取未保存草稿。

### 3.2 资产 Sheet

资产 Sheet 回答“我拥有什么”，负责资产主数据 CRUD。

建议默认列：

| 列 | 类型 | 权限 | 说明 |
|---|---|---|---|
| 名称 | 文本 | 可编辑 | 必填 |
| 类型 | 枚举 | 可编辑 | 基金、股票、黄金、存款、现金、公积金、其他 |
| 标识 | 文本 | 可编辑 | 按类型展示基金代码、股票代码或自定义识别字段 |
| 机构 | 文本 | 可编辑 | 银行、券商、平台等 |
| 币种 | 枚举 | 可编辑 | CNY、USD、HKD |
| 最新金额 | 金额 | 只读 | 来自最新快照 |
| 收益 | 金额 | 只读 | 投资类资产来自最新快照，余额类显示 `-` |
| 收益率 | 百分比 | 只读 | 投资类资产来自最新快照，余额类显示 `-` |
| 状态 | 枚举 | 可编辑 | 启用或停用；停用代替物理删除 |
| 备注 | 文本 | 可编辑 | 可选 |

交互规则：

- 最后一行提供新增资产入口。
- 新增或修改行先进入草稿，点击“保存资产”后整批提交。
- 最新金额、收益和收益率使用只读样式；点击可跳转到录入 Sheet 并定位资产。
- 修改资产类型时，系统清理不再适用的类型档案字段。
- 停用资产不会删除历史快照引用，也不会出现在新的录入表中。
- 复杂的类型档案和定投配置可以使用行展开区域；第一版不要求把所有字段横向铺开。

### 3.3 录入 Sheet

录入 Sheet 回答“这些资产现在值多少”。它不是资产编辑器，而是一次快照 append 操作。

进入页面时：

1. 加载所有启用资产。
2. 为每项资产预填一行。
3. 读取最新快照，把上次金额、收益和收益率带入本次可编辑列。
4. 默认使用当前日期作为快照日期，用户可以修改。
5. 未修改的资产保持继承值，用户只需修改发生变化的单元格。

建议列：

| 列 | 类型 | 权限 | 说明 |
|---|---|---|---|
| 名称 | 文本 | 只读 | 来自资产主数据 |
| 类型 | 枚举 | 只读 | 来自资产主数据 |
| 标识 | 文本 | 只读 | 用于识别资产 |
| 机构 | 文本 | 只读 | 来自资产主数据 |
| 币种 | 枚举 | 只读 | 来自资产主数据 |
| 上次金额 | 金额 | 只读 | 上一份快照状态 |
| 本次金额 | 金额 | 可编辑 | 默认带入上次金额 |
| 收益 | 金额 | 条件可编辑 | 仅投资类资产可编辑 |
| 收益率 | 百分比 | 条件可编辑 | 仅投资类资产可编辑 |
| 备注 | 文本 | 可编辑 | 本次资产状态备注 |

页面顶部显示：

- 快照日期。
- 上次快照日期。
- 本次已修改的资产数量。
- 本次总资产及相对上次的变化预览。
- “追加快照”主操作。

点击“追加快照”后：

1. 前端校验所有可编辑单元格。
2. 余额类资产不能携带收益和收益率。
3. 未修改资产继续使用预填值。
4. 服务端按现有 `completeSnapshotValues` 语义保存一份完整快照。
5. 保存成功后清空草稿，并使大盘读取新的最新快照。

录入 Sheet 支持方向键、Tab 连续录入和从 Excel 粘贴矩形区域。复制粘贴仍必须经过相同的字段校验。

### 3.4 收入 Sheet

收入 Sheet 回答“我获得了什么”，负责收入事件 CRUD。

建议列：

| 列 | 类型 | 权限 |
|---|---|---|
| 日期 | 日期 | 可编辑 |
| 分类 | 枚举 | 可编辑 |
| 金额 | 金额 | 可编辑 |
| 来源 | 文本 | 可编辑 |
| 备注 | 文本 | 可编辑 |

交互规则：

- 最后一行用于新增收入。
- 删除行为先标记为待删除，保存时统一提交。
- 支持按日期、分类和来源排序或筛选。
- 点击“保存收入”后整批校验并提交。

### 3.5 数据 Sheet

数据 Sheet 承担低频的数据交换和恢复操作：

- 导出 JSON 完整备份。
- 从 JSON 完整恢复。
- 导出 Excel 工作簿。
- 从 Excel 批量导入或完整恢复。
- 展示导入预览、校验问题和覆盖范围。

数据 Sheet 不参与日常资产录入。

## 4. 通用表格交互

所有可编辑 Sheet 使用统一的受控表格交互：

- 单击选中单元格，双击或直接输入进入编辑。
- Enter 确认并移动到下一行，Tab 移动到下一列。
- 支持方向键移动、复制、粘贴和矩形区域填充。
- 枚举字段使用单元格下拉选择。
- 日期、金额和百分比使用对应的受控输入与展示格式。
- 冻结表头和关键识别列。
- 修改过的单元格使用统一的未保存标记。
- 错误单元格使用错误边框，并提供简短原因。
- 计算值和系统字段使用统一的只读样式。

表格工具栏保持精简：

```text
筛选 | 排序 | 新增行 | 放弃修改 | 保存
```

不复制 Excel 的字体、颜色、合并单元格、公式等通用编辑能力。

## 5. 草稿与保存状态

每个可编辑 Sheet 使用相同状态机：

```text
clean
  -> editing
  -> validating
  -> saving
  -> clean

validating -> editing  校验失败
saving -> editing      服务端保存失败
editing -> clean       放弃修改
```

约束：

- 保存期间禁止再次编辑和重复提交。
- 保存失败后保留原草稿。
- 服务端返回的字段错误需要映射到对应行列。
- 同一批修改应全部成功或全部失败。
- 大盘及其他 Sheet 只读取服务端已保存数据。

## 6. Excel 导入导出

Excel 是工作簿式界面的交换格式，不是另一套独立产品模型。

### 6.1 完整工作簿导出

完整导出包含：

```text
使用说明
资产
快照
快照值
收入
汇率
```

这些 Sheet 保留稳定的机器字段映射，以便完整恢复。大盘属于派生展示，不作为恢复数据源。

### 6.2 批量录入模板

第一版优先提供“快照录入模板”：

- 下载时自动带入当前启用资产和上次状态。
- 用户只填写本次金额、收益、收益率和备注。
- 上传后先展示新增快照的变化预览。
- 校验通过并确认后，按一次快照 append 保存。

后续可以增加资产和收入批量维护模板，但不把不同保存语义混在一次导入中。

### 6.3 导入安全

- 批量录入和完整恢复使用不同入口。
- 完整恢复必须明确提示会覆盖当前账本。
- 上传后先解析、校验和预览，确认前不写入服务端。
- 错误需要显示 Sheet、行号、列名和原因。
- 导入必须复用服务端领域校验，不能只依赖前端检查。

## 7. 技术边界

### 7.1 前端

前端负责：

- 表格展示和键盘交互。
- 当前 Sheet 草稿及脏单元格追踪。
- 即时格式校验和保存前预校验。
- 将表格修改转换为明确的批量命令。

建议建立通用表格基础层，但不把领域规则写入通用组件：

```text
EditableGrid
  <- AssetsSheet column schema and adapter
  <- SnapshotEntrySheet column schema and adapter
  <- IncomeSheet column schema and adapter
```

### 7.2 Worker API

Worker 继续拥有最终校验和 KV 持久化职责。为了保证 Sheet 级原子保存，应提供与业务语义对应的批量接口，而不是让前端逐单元格调用接口：

- 资产批量保存。
- 收入批量保存。
- 追加完整快照。
- Excel 导入预览和确认，或由前端解析后提交等价批量命令。

当前单用户、低频写入模型不需要引入通用数据库、协同编辑或复杂版本系统。

### 7.3 领域规则归属

- 资产与快照边界继续由现有领域模型定义。
- 快照补全规则保持不变。
- 金额、收益率、资产类型和币种校验必须由服务端最终执行。
- 需要跨 Web、小程序和 Worker 复用的纯规则应逐步进入 `modules/finance-core`。

## 8. 错误处理

- 格式错误：直接标记单元格，例如金额不是有效数字。
- 行级错误：标记整行，例如缺少资产名称。
- 关系错误：显示明确对象，例如快照引用了不存在的资产。
- 保存失败：保留草稿，并在工具栏显示失败原因。
- Excel 文件错误：展示 Sheet、单元格坐标和修复建议。
- 网络失败：允许用户再次保存，不清空草稿。

## 9. 测试策略

### 9.1 领域与适配测试

- 资产表格行与 `Asset` 的双向映射。
- 收入表格行与 `IncomeRecord` 的双向映射。
- 录入表预填上次快照值。
- 未修改资产在保存后正确继承。
- 余额类资产禁用并拒绝收益字段。
- 百分比和金额格式化不会改变存储语义。

### 9.2 交互测试

- 编辑后出现未保存状态。
- 放弃修改恢复服务端基线。
- 切换 Sheet 时出现三选一确认。
- 校验失败时定位到错误单元格。
- 复制粘贴矩形区域后正确生成草稿。
- 保存期间禁止重复提交。

### 9.3 API 测试

- 批量保存全成功或全失败。
- 追加快照仍保存完整时点。
- 导入非法 Excel 数据不会改变原账本。
- JSON 旧备份继续兼容。

### 9.4 Excel 测试

- 导出工作簿可被 Excel 正常打开。
- 数字、日期和百分比保持真实单元格类型。
- 完整工作簿可以无损恢复。
- 快照模板导入后与应用内直接录入结果一致。

## 10. 分阶段实施

### 阶段一：录入 Sheet

优先把现有快照表单改造成预填全部启用资产的表格式录入。这一阶段复用现有快照保存规则，最直接验证表格交互价值。

### 阶段二：资产 Sheet

把资产列表和编辑表单整合为可编辑表格；最新金额、收益和收益率保持只读。

### 阶段三：收入 Sheet

把收入管理改造成统一表格 CRUD，并复用草稿和保存机制。

### 阶段四：工作簿导航与大盘收敛

将大盘明确为纯 View，统一顶部 Sheet 导航、未保存提示和视觉语言。

### 阶段五：Excel 交换

先实现快照录入模板，再实现完整工作簿导出与恢复。JSON 备份继续作为稳定的原始恢复格式。

## 11. 成功标准

- 用户进入录入 Sheet 后无需逐个选择资产即可完成一次快照。
- 只修改发生变化的单元格即可保存完整快照。
- 资产、收入和录入使用一致的编辑、校验和保存语言。
- 用户能清楚区分资产主数据修改与快照状态追加。
- 大盘只展示已保存结果，不承担编辑职责。
- Excel 批量录入与应用内录入遵循同一领域规则。
- 第一版不引入自动保存、通用公式或多用户协同复杂度。
