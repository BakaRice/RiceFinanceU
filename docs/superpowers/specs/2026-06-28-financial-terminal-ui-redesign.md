# 金融终端型 UI 重设计方案

日期：2026-06-28

## 背景

RiceFinanceU 当前已经具备资产管理、快照录入、总览和数据管理等基础能力，但界面气质仍偏普通管理后台。用户反馈集中在几个细节：

- 金额展示不够精致，尤其详情页小数部分应弱化展示。
- 编辑金额时小数位处理不够自然，没有形成金融录入应有的精确感。
- 页面整体信息密度偏低，录入和查看资产时效率不够高。
- 系统 `alert`、`confirm` 或普通 Toast 风格不够优雅，关键操作缺少可信的页面内反馈。
- 整体 UI 缺少统一的金融软件展示规则。

本方案只定义 UI 设计和交互规划，不进入具体技术实现。

## 设计目标

1. 让产品从普通后台界面升级为轻量个人金融终端。
2. 建立统一的金额、收益、收益率、小数、币种和空值展示规则。
3. 提高资产管理和快照录入的信息密度，让长期使用更高效。
4. 用页面内反馈替代浏览器原生弹窗和轻飘的 Toast。
5. 让详情页围绕“当前金额、变化、来源时间”建立清晰阅读层级。
6. 保持克制、安静、精确，不做营销化、装饰化或过度卡片化设计。

## 非目标

- 不引入复杂图表、行情、交易流水或自动估值。
- 不做品牌视觉大改，不添加插画、渐变背景或装饰性元素。
- 不把页面改成移动端 App 风格。
- 不在本方案中定义具体 React 组件拆分、状态管理或测试计划。
- 不追求炫技动画，所有动效只服务于反馈和状态变化。

## 总体设计方向

采用“金融终端型”UI：

- 主形态是高密度表格、清晰数字层级和稳定操作区。
- 美感来自对齐、间距、数字格式、状态色和反馈秩序。
- 页面减少大卡片、大留白、大圆角和强阴影。
- 重要信息优先展示，说明性文字减少。
- 金额和收益类数字成为视觉中心，备注、机构、类型等辅助信息降级。

产品气质关键词：

- 精确。
- 克制。
- 安静。
- 可信。
- 高效。

## 视觉语言

### 色彩

整体色彩应偏中性金融工具感：

- 页面背景使用浅中性灰，避免偏蓝过重。
- 主色使用低饱和金融蓝或深青色，不使用高亮互联网蓝。
- 正收益使用克制绿色，负收益使用克制红色。
- 中性信息使用灰阶，不用过多彩色标签。
- 警告和危险操作只在必要处使用红色。

颜色使用原则：

- 金额本身通常不使用高饱和色。
- 正负收益可以用颜色，但必须同时保留 `+` 或 `-` 符号。
- 类型标签颜色应弱化，不要和金额抢注意力。
- 关键按钮可以有主色，但页面内不应出现大面积主色块。

### 字体与数字

- 使用系统字体即可。
- 所有金额、收益、收益率、数量统计使用等宽数字或 `tabular-nums`。
- 数字列右对齐。
- 文本列左对齐。
- 表头字号应小于表格正文，颜色更弱。
- 详情页主金额可以使用更大字号，但不应做营销页式大标题。

### 边框、圆角和阴影

- 优先使用 1px 边框建立结构。
- 阴影只用于浮层和确认弹窗，不用于普通页面区块。
- 圆角控制在 4-8px。
- 表格、输入框、按钮的圆角保持一致。
- 不使用大面积浮动卡片堆叠。

## 数字展示规范

### 金额结构

金额展示应拆为四层：

1. 货币符号，例如 `¥`、`$`、`HK$`。
2. 整数部分，例如 `12,345`。
3. 小数部分，例如 `.67`。
4. 币种，例如 `CNY`、`USD`、`HKD`。

推荐视觉：

- 整数部分是主体。
- 小数部分字号降低、颜色略弱，并与整数基线对齐。
- 币种作为辅助标签，字号低于整数部分。

示例语义：

```text
¥12,345.67 CNY
```

视觉上应理解为：

```text
¥ + 12,345 + .67 + CNY
```

而不是一整段同权文本。

### 金额展示规则

- 金额展示永远保留两位小数。
- 整数部分使用千分位。
- 空值显示 `-`。
- 未知值不得显示为 `0.00`。
- 金额列右对齐。
- 同一页面内货币符号和币种不能混用成不同语义；符号表示可读性，币种表示准确性。

### 收益展示规则

- 正收益显示 `+1,234.56`。
- 负收益显示 `-1,234.56`。
- 零收益显示 `0.00`，使用中性色。
- 正负收益使用颜色区分，但颜色只是辅助。
- 收益小数部分同样弱化展示。

### 收益率展示规则

- 展示为百分比，例如 `8.65%`。
- 永远保留两位小数。
- 正收益率显示 `+8.65%`。
- 负收益率显示 `-8.65%`。
- 收益率不能小于 `-100.00%`。

## 编辑与输入规范

金融录入需要区分“输入中”和“失焦后”两种状态。

### 输入中

输入框应允许用户自然输入中间态：

- `12.`
- `.5`
- `-`
- `-12.`

但必须限制明显非法内容：

- 金额只能输入非负数字。
- 收益可以输入负数。
- 收益率可以输入负数，但不能小于 `-100`。
- 金额、收益、收益率最多允许两位小数。
- 粘贴内容超过两位小数时，按截断处理。

这里建议采用截断，而不是四舍五入。原因是金融录入中用户更容易信任“我输入了什么就保留什么”，自动四舍五入可能制造误差感。

### 失焦后

失焦后统一格式化：

- `12` 变为 `12.00`。
- `12.3` 变为 `12.30`。
- `12.3456` 变为 `12.34`。
- `.5` 变为 `0.50`。
- 空输入保持空，不自动变成 `0.00`。

输入框旁边可以固定显示单位：

- 金额字段显示币种。
- 收益率字段显示 `%`。

### 自动计算

投资类资产的金额、收益、收益率可以继续互相推导，但 UI 必须明确哪个字段是用户刚刚编辑的、哪些字段是系统计算出的。

推荐规则：

- 用户编辑的字段保持普通输入状态。
- 自动计算出的字段短暂显示“已计算”状态。
- 自动计算结果仍按两位小数截断或格式化。
- 不在用户输入中间态时强制自动计算。

## 信息密度规范

### 页面密度

页面应减少解释性文字和大块留白。核心操作区保持紧凑：

- 表格行高控制在 40-48px。
- 表头高度控制在 32-36px。
- 表格容器内边距控制在 12-16px。
- 页面主内容最大宽度可以放宽，充分利用横向空间。
- 常用操作应靠近数据本身。

### 表格密度

资产管理页和快照录入页应优先使用表格或表格化网格，不使用一项一个大卡片的主结构。

表格列优先级：

1. 资产名称。
2. 最新金额或本次金额。
3. 变化金额。
4. 收益。
5. 收益率。
6. 类型、机构、币种。
7. 备注。
8. 操作。

辅助列可以更窄、更弱，避免挤压金额列。

## 页面设计规划

### 资产管理页

资产管理页应成为资产主数据和最新状态的高密度列表。

#### 页面结构

顶部：

- 页面标题 `资产管理`。
- 简短统计：启用资产数、停用资产数、币种数量。
- 主操作：新增资产。

主体：

- 已启用资产表格。
- 已停用资产折叠或弱化展示。

表格建议列：

- 名称。
- 类型。
- 机构。
- 币种。
- 最新金额。
- 收益。
- 收益率。
- 更新时间。
- 备注。
- 操作。

#### 设计重点

- 最新金额列是主视觉，应右对齐并使用金额分层展示。
- 类型和币种标签应更轻，不要过度彩色。
- 停用资产不应只靠透明度表达，应有明确状态标签。
- 操作区不要出现多个强文本按钮，可以收敛为轻量操作或更多菜单。
- 表格排序状态要清晰，但图标要克制。

### 快照录入页

快照录入页应像一张高效的资产盘点单。

#### 页面结构

顶部固定摘要区：

- 快照日期。
- 快照时间。
- 备注。
- 本次更新项数。
- 金额变化项数。
- 大额变化项数。
- 保存按钮。

主体：

- 投资类资产表格。
- 余额类资产表格。

表格建议列：

- 勾选。
- 资产名称。
- 类型或机构。
- 上次金额。
- 本次金额。
- 变化。
- 当前收益。
- 收益率。
- 状态。

#### 设计重点

- 输入框应该内嵌在表格中，而不是一行一个大卡片。
- 已勾选行、已修改行、异常变化行要有不同但克制的状态。
- 未勾选行应弱化，但仍可读。
- 保存按钮应始终易于触达，避免滚到底部才能保存。
- 空资产状态应直接引导去资产管理新增资产。

### 资产详情页

资产详情页应围绕“最新状态”组织，而不是平均展示所有字段。

#### 页面结构

头部：

- 资产名称。
- 状态。
- 类型。
- 机构。
- 币种。

主指标区：

- 最新金额。
- 收益。
- 收益率。
- 更新时间。

明细区：

- 基础信息。
- 最新快照。
- 历史变化。
- 备注。
- 操作。

#### 设计重点

- 最新金额使用最大视觉层级。
- 小数部分在详情页必须弱化，字号小于整数部分。
- 更新时间要靠近金额，说明数字来源。
- 收益和收益率作为二级指标，不和主金额抢层级。
- 基础信息用紧凑描述列表，不做大卡片堆叠。

### 总览页

总览页应强调资产规模和变化，不做过多装饰。

建议结构：

- 顶部展示总资产、较上次变化、快照时间。
- 下方展示按资产类型或币种的紧凑分布。
- 最近快照变化使用表格或简洁列表。
- 避免大面积彩色卡片和装饰性图形。

## 反馈与弹窗规划

### 反馈分级

反馈分为三类：

1. 轻反馈。
2. 中反馈。
3. 强反馈。

### 轻反馈

用于保存成功、字段自动计算、数据刷新完成等场景。

形式：

- 页面内 banner。
- 表单区域内状态条。
- 行内状态文本。

示例：

```text
快照已保存 · 2026-06-28 21:30 · 更新 12 项
```

轻反馈可以自动淡出，但不应突然消失；关键操作可以保留到下一次编辑。

### 中反馈

用于保存前复核。

形式：

- 页面内确认面板。
- 轻量 modal。

内容：

- 快照时间。
- 本次更新资产数量。
- 金额变化数量。
- 大额变化资产。

### 强反馈

用于停用资产、离开未保存内容、删除或导入覆盖数据等场景。

形式：

- 设计过的确认弹窗。
- 明确标题。
- 明确后果说明。
- 主操作和取消操作视觉层级清晰。

不再使用浏览器原生 `alert` 和 `confirm` 作为最终 UI。

## 状态设计

### 行状态

表格行至少支持：

- 默认。
- hover。
- selected。
- edited。
- disabled。
- warning。
- inactive。

状态应通过背景、边框、文字权重或状态标签组合表达，不只依赖透明度。

### 输入状态

输入框至少支持：

- 默认。
- 聚焦。
- 已修改。
- 自动计算。
- 错误。
- 禁用。

错误状态必须靠近字段展示，不只在页面顶部提示。

### 空状态

空状态应该短而直接：

```text
暂无资产项。先新增资产，再录入快照。
```

空状态不需要插画。

## 移动端规划

移动端不应简单压缩桌面表格。

建议：

- 资产管理页移动端使用紧凑列表，每项突出金额和收益。
- 快照录入页移动端使用分组折叠列表，编辑字段纵向展开。
- 主操作固定在底部。
- 金额仍保持小数弱化和币种辅助展示。

桌面端优先服务高密度管理，移动端优先服务快速查看和少量编辑。

## 优先级

### 第一阶段：建立金融 UI 基础规则

1. 金额、小数、币种、收益、收益率展示规范。
2. 输入中和失焦后的数字处理规范。
3. 表格密度、列对齐、行高、状态色规范。
4. 页面内反馈替代原生弹窗。
5. 统一按钮、输入框、表格、标签的视觉风格。

### 第二阶段：重设计核心页面

1. 资产管理页改为更高密度的金融表格。
2. 快照录入页改为盘点单式表格录入。
3. 资产详情页建立主数字和明细矩阵。
4. 总览页弱化装饰，强化规模和变化。

### 第三阶段：细节打磨

1. 移动端单独适配。
2. 自动计算状态提示。
3. 异常变化提示。
4. 空状态和错误状态统一。
5. 微动效和过渡节奏统一。

## 验收标准

1. 金额展示能区分整数、小数、符号和币种层级。
2. 详情页主金额的小数部分明显小于整数部分。
3. 金额、收益、收益率均使用统一的小数和千分位规则。
4. 编辑金额时最多保留两位小数，粘贴长小数按截断处理。
5. 输入中允许合理中间态，失焦后统一格式化。
6. 资产管理页信息密度高于当前版本，金额列成为视觉中心。
7. 快照录入页从卡片式录入转向盘点单式录入。
8. 成功、失败、保存前复核和危险确认均使用页面内反馈。
9. 页面不再依赖浏览器原生 `alert` 和 `confirm` 作为主要反馈。
10. 视觉语言保持克制，不使用大面积装饰、强阴影或营销式卡片布局。

## 设计结论

RiceFinanceU 的 UI 升级重点不是简单美化，而是建立金融数据产品的秩序感。数字应该被精细排版，录入应该尊重金融精度，页面应该提高密度，反馈应该沉在界面里。完成这些后，产品会更像一个可信赖的个人资产终端，而不是一个普通数据管理页面。
