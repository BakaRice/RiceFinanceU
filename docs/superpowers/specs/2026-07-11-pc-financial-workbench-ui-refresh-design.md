# PC 金融工作台 UI 焕新设计

日期：2026-07-11

## 背景

RiceFinanceU 的 PC Web 端已经具备金额分层、金融表格、页面内反馈和统一主题变量等基础能力，但真实页面仍然呈现出明显的通用管理后台气质：导航体量与内容失衡、首页模块等权堆叠、页面层级偏弱、表格操作散乱，登录与数据管理页面也没有延续金融工具的产品气质。

本轮改造不重新定义产品模型，也不增加复杂功能。目标是在保留现有业务能力的前提下，把 PC Web 端统一成精致、克制、耐看且适合长期自用的个人金融工作台。

## 目标

1. 建立完整、统一的 PC 端视觉语言，而不是只给现有后台换颜色。
2. 让总资产、资产变化和趋势成为总览页的明确视觉中心。
3. 提高资产管理和快照录入的扫描效率与编辑可信度。
4. 收敛分散的按钮、卡片、空状态和危险操作。
5. 修复直接破坏观感的数字格式问题，特别是收益率长小数。
6. 保持轻量，不引入大型 UI 组件库或额外运维成本。

## 非目标

- 不修改 `Asset`、`Snapshot`、`SnapshotValue` 的领域边界。
- 不修改 Cloudflare Worker API 和数据存储。
- 不修改微信小程序。
- 不增加行情、交易流水、自动估值或复杂分析功能。
- 不制作全黑、重度交易终端式界面。
- 不增加装饰性插画、渐变背景、炫技动画或营销文案。

## 设计原则

### 精确

金额、收益、收益率、币种和时间来源必须易于确认。数字采用等宽数字特性并严格右对齐，正文不使用代码字体。

### 克制

美感来自排版、灰阶、间距、对齐和信息优先级。主色、状态色、圆角和阴影都限制在必要场景。

### 高效

常用数据和操作出现在扫描路径上。辅助信息收拢，不让备注、机构、标签和行内操作挤压金额列。

### 可信

保存、删除、停用、导入等操作必须有明确语义和反馈。不能使用含义模糊的 `✕` 代替删除，也不能以轻飘提示代替关键确认。

## 视觉系统

### 色彩

- 页面背景使用温和的浅石灰色，避免冷灰背景让界面显得发闷。
- 数据表面使用白色，层级主要由细边框和背景差异建立。
- 导航使用深灰蓝，而不是接近纯黑的色块。
- 金融蓝只用于当前状态、主操作、焦点和趋势线。
- 正收益使用低饱和绿色，负收益使用低饱和红色。
- 警告色仅标识需要注意的变化或危险操作。

### 字体与数字

- 中文正文使用系统无衬线字体栈。
- 金额、收益率、日期数量使用 `font-variant-numeric: tabular-nums`。
- 金额继续拆分为符号、整数、小数和币种四层。
- 整数是主体，小数和币种降级，但必须保持基线稳定。
- 页面标题不再使用过大的孤立黑体，层级通过位置、字重和辅助信息建立。

### 形状与层级

- 常规圆角统一在 4-6px。
- 普通页面区块不使用阴影。
- 弹窗、菜单、浮层允许使用轻阴影。
- 数据区块优先使用共享边框或分隔线，不堆叠大量独立卡片。
- 动效仅用于焦点、保存反馈、菜单出现和状态切换，持续时间保持简短。

### 页面宽度

取消当前内容区统一 `max-width: 1200px` 的限制：

- 总览、资产管理和快照录入允许使用 1360-1440px 的工作宽度。
- 资产详情控制在约 1080-1160px。
- 数据管理控制在约 760-880px。
- 内容区必须在常见 PC 宽度下保持稳定，不因为固定宽度产生不必要的空白或横向挤压。

## 应用骨架与导航

### 侧栏

- 侧栏改为更轻、更精致的深灰蓝导航轨道。
- 顶部采用简化品牌标识与 `Rice Finance` 名称，中文产品含义作为弱辅助信息。
- 总览、资产管理、快照录入和数据管理增加风格一致的线性图标。
- 当前页面使用浅色选中背景、清晰文字和左侧强调线。
- 退出操作放入底部账户区域，视觉级别低于业务导航。
- PC 端保持固定侧栏，不增加复杂折叠逻辑。

### 统一页头

每个页面都采用同一页头结构：

1. 页面标题。
2. 必要的状态或时间说明。
3. 页面唯一的主操作。
4. 可选的次级工具区。

不再出现只有一个大标题、下方直接开始堆内容的页面。

## 总览页

### 第一层：资产摘要带

- 使用一个连续的资产摘要带替代多个等权卡片。
- 总资产是绝对主视觉。
- 较上次变化、投资类、余额类和投资收益作为次级指标。
- 明确显示最近快照时间，回答“这些数字截至什么时候”。
- 汇率信息放在摘要带右上角，修改入口使用明确的小型按钮。
- 数据为空时不伪造 `0.00`，继续使用 `-` 和清晰空状态。

### 第二层：总资产趋势

- 趋势图成为页面最大的核心模块。
- 日、周、月、季、年切换改为紧凑分段控件。
- 减少网格线和坐标轴噪声，强化趋势线和关键节点。
- Tooltip 统一展示周期、实际快照时间和两位小数金额。
- 收入数据存在时可继续叠加，但视觉级别低于总资产趋势。

### 第三层：结构与变化

- 使用左右双栏：资产类别占比与最近变化。
- 占比条允许使用一组低饱和分类色，但不能形成彩虹式噪声。
- 类别名称、金额、百分比采用稳定列对齐。
- 最近变化突出资产名称、变化金额和变化比例，弱化上次与本次的重复视觉。

### 月收入

- 有记录时显示紧凑的最近月收入摘要。
- 无记录时只显示一条小型提示与“记录收入”操作。
- 收入表单继续使用页面内面板或轻量弹窗，不让空状态长期占据大块首屏空间。

### 快照历史

- 改为紧凑时间线表格或列表。
- 每行展示时间、备注、总金额和资产项数。
- 删除操作收进明确的行尾菜单，菜单项必须写“删除快照”。
- 删除仍使用确认对话框，并展示将删除的快照时间。

## 资产管理页

### 页头与统计

- 页头展示启用数量、停用数量和当前币种范围。
- `新增资产` 是页面唯一主按钮。
- 不新增搜索、筛选等当前不必要的功能。

### 资产表格

- 保留现有信息，但重新组织视觉列。
- 资产名称为主文本，机构或关键标识作为第二行辅助信息。
- 类型和币种使用低饱和小标签。
- 最新金额、收益和收益率严格右对齐并提高扫描优先级。
- 备注限制为一行并截断，完整内容在资产详情中查看。
- `编辑` 和 `停用` 收进一个行尾操作菜单。
- 资产名称或整行提供清晰的详情入口。
- 排序箭头统一为克制图标，当前排序状态必须可见。

### 停用资产

- 停用资产独立折叠显示。
- 使用明确的停用状态标签，不依赖透明度表达。
- 恢复操作使用普通次级操作，永久删除如果不存在则不新增。

### 新增与编辑

- 表单字段按“基本信息、类型档案、备注”分组。
- 保持资产主数据与快照金额录入的现有边界。
- 金额仍为只读的最新快照状态，不能在资产编辑表单中修改。

## 快照录入页

### 吸顶工具栏

- 日期、时间、备注、更新数量、变化数量和保存按钮组成一条吸顶工具栏。
- 保存按钮固定在最右侧并保持可见。
- `管理资产` 作为清晰的次级入口，继续承担返回资产主数据管理的职责。
- 工具栏在宽度不足时允许有序换行，但不能遮挡表格。

### 录入表格

- 投资类与余额类继续分组，保持现有产品语义。
- 上次金额弱化，本次金额强化，变化金额置于两者附近。
- 修改行采用轻微背景与左侧状态线，不使用大面积高亮。
- 大额变化使用警告图标、文字与局部颜色，不整行铺黄。
- 输入框拥有明确的默认、焦点、已修改、自动计算和错误状态。
- 取消勾选后行仍可识别，但不能仅依赖大幅降低透明度。

### 数字输入修复

- 金额和收益失焦后统一显示两位小数。
- 收益率输入和展示统一为两位小数。
- 从快照加载的 `30.769230769...` 等值在进入输入框前格式化为 `30.77`。
- 中间输入态继续允许 `12.`、`.5` 和 `-` 等合法过程值。
- 自动计算结果显示轻量“已计算”状态，不改变领域计算规则。

### 保存确认

- 保存前确认面板分为快照摘要、总变动和变化明细三部分。
- 明确显示快照时间、更新数量、变化数量和大额变化。
- 明细使用对齐列表，不用一整段带换行符的纯文本。
- 保存成功后给出页面内反馈，并保持用户对当前状态的理解。

## 资产详情页

- 页头同时展示资产名称、类型、机构、币种和启用状态。
- 编辑入口位于页头，避免内容区重复操作。
- 当前金额为主视觉，收益和收益率紧邻展示。
- 最近快照时间作为金额的数据来源说明。
- 基本资料、类型档案、定投计划和历史记录使用清晰分区。
- 不同分区可以共享页面边框体系，但不堆成同权卡片。
- 历史记录突出时间、金额和变化，保持紧凑表格结构。
- 没有内容的模块不展示大面积空框。

## 登录页

- 保持单一登录流程，不增加宣传内容和注册入口。
- 使用精确排版、轻量品牌标识和更自然的背景层级。
- 表单区域减少模板化白卡感，输入框和按钮沿用主应用视觉系统。
- 错误提示显示在表单内部，并与对应操作保持空间关联。

## 数据管理页

- 将导出、导入和风险说明分为清晰区块。
- 导出是普通操作，导入是需要文件状态和校验反馈的流程。
- 导入后的问题列表保持可扫描，并区分错误与警告。
- 危险或覆盖性操作使用独立警示区，不能与普通按钮并排混放。
- 页面保持窄内容宽度，避免简单功能被拉成大面积空白页面。

## 反馈与操作组件

### Toast

- 仅用于保存成功、轻量错误和短暂状态。
- 文案简短，不能承载大段变化明细。
- 成功、错误和警告拥有一致图标与色彩语义。

### 确认对话框

- 标题直接说明动作。
- 内容明确说明对象和后果。
- 危险操作的确认按钮使用危险色，取消按钮保持中性。
- 保存快照等复杂确认使用结构化内容区域。

### 行尾菜单

- 资产编辑、停用和快照删除统一通过行尾菜单承载。
- 菜单必须可通过键盘聚焦，并具有清晰文本标签。
- 不能用只有符号、没有语义的操作代替菜单项。

## 可访问性与 PC 适配

- 正负变化不能只依赖颜色，必须保留正负号和文字。
- 交互控件保留明显焦点环。
- 图标按钮必须提供可访问名称。
- 表格在较窄桌面视口允许横向滚动，但主要列应优先可见。
- 本轮以 1024px 以上 PC 视口为目标，不承担微信小程序或完整移动端重构。

## 验收标准

1. 所有 PC 页面具有统一的导航、页头、按钮、表格和反馈语言。
2. 总览页第一屏能快速回答总资产、最近变化、数据时间和趋势。
3. 资产管理页的金额列优先级明显高于备注和操作。
4. 快照录入页不存在长串收益率小数，输入状态与自动计算状态清晰。
5. 页面中不再出现使用 `✕` 表达删除的模糊操作。
6. 空状态不会占据与真实数据相同的大块空间。
7. 1024px 以上常见 PC 视口下无非必要横向溢出。
8. 原有业务流程、数据模型和 API 行为保持不变。
9. `npm run test` 和 `npm run build` 通过。
