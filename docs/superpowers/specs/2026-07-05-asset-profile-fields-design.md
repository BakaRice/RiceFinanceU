# 资产类型档案字段设计

日期：2026-07-05

## 背景

RiceFinanceU 当前的资产管理页已经承担资产主数据维护职责，快照录入页负责记录某个时间点的资产状态。现有资产字段包括名称、类型、币种、机构、状态和备注。这个模型清晰，但资产类型只是分类标签，无法表达不同类型资产在管理上需要的识别信息。

本次设计将资产管理从“资产清单”升级为“资产档案”。资产档案只补充长期稳定、用于识别和管理的属性，不引入估值辅助能力。

## 产品边界

资产管理负责：

- 资产基础信息。
- 按类型区分的档案信息。
- 资产启用、停用和备注。

快照录入负责：

- 快照时间。
- 本次资产金额。
- 投资类资产的收益和收益率。
- 快照和快照值备注。

本次不把份额、净值、持仓数量、成本、自动收益计算、自动估值或交易流水加入资产档案。资产档案不影响快照补全、汇总、走势和收益计算。

## 产品目标

1. 让不同类型资产具备适当的识别和管理属性。
2. 保持新增资产流程轻量，所有类型档案字段第一版均为可选。
3. 在资产列表中展示少量关键标识，提高检索效率。
4. 在资产详情页展示完整资产档案，和金额、收益、历史快照分区。
5. 保持现有快照账本模型稳定，不引入持仓分析模型。

## 非目标

- 不记录当前份额、当前股数、当前克重、成本、净值或金价。
- 不基于档案字段自动计算金额、收益或收益率。
- 不新增交易、订单、产品、账户拆分模型。
- 不做行情接口、到期提醒推送或利息自动计提。
- 不要求用户填写全部字段。

## 信息模型

资产继续保留通用字段：

- 名称。
- 类型。
- 币种。
- 平台或机构。
- 启用状态。
- 备注。

新增可选字段 `profile`，用于保存类型档案信息。`profile` 是资产主数据的一部分，和 `SnapshotValue` 没有计算关系。

示意：

```ts
type Asset = {
  id: string
  name: string
  type: AssetType
  institution?: string
  currency: Currency
  isActive: boolean
  note?: string
  profile?: AssetProfile
  createdAt: string
  updatedAt: string
}
```

## 类型档案字段

### 基金

- 基金代码。
- 基金类别。
- 投资市场或主题。
- 持有平台。

示例：`513100`、`指数基金`、`美股/纳指100`、`蚂蚁财富`。

### 股票

- 证券代码。
- 交易市场。
- 券商或账户。
- 行业或策略标签。

示例：`AAPL`、`NASDAQ`、`富途证券`、`科技/长期持有`。

### 黄金

- 持有形态。
- 持有平台或保管方。
- 计量单位。
- 来源备注。

示例：`积存金`、`支付宝`、`克`、`手动盘点`。

### 存款

- 银行。
- 存款类型。
- 期限。
- 到期日。
- 约定年利率。

约定年利率仅作为合同档案信息展示，不参与利息或收益计算。

### 现金

- 账户渠道。
- 用途标签。
- 可用性备注。

示例：`微信零钱`、`日常备用`、`随时可用`。

### 公积金

- 缴存城市。
- 账户归属。
- 管理中心或单位备注。

示例：`上海`、`本人`、`市公积金中心`。

### 其他

- 自定义分类。
- 权属说明。
- 管理备注。
- 到期或提醒日期。

到期或提醒日期第一版只展示，不做通知。

## 页面设计

### 资产列表

资产列表新增“标识”列，只展示每种类型最有检索价值的一段档案信息：

- 基金：基金代码。
- 股票：交易市场 + 证券代码。
- 黄金：持有形态。
- 存款：到期日。
- 现金：账户渠道。
- 公积金：缴存城市。
- 其他：自定义分类。

如果没有可展示标识，显示 `-`。完整档案不在列表铺开，避免破坏金融终端式信息密度。

### 新增和编辑资产

资产弹窗分成两段：

1. 基础信息：名称、类型、币种、机构、备注。
2. 类型档案：根据资产类型切换字段。

类型档案字段全部可选。切换类型时，只展示当前类型使用的字段；系统保存时只保留当前类型相关字段，避免历史隐藏字段污染档案。

### 资产详情

资产详情页在“基础信息”和“历史变化”之间增加“资产档案”区域。该区域按类型展示完整档案字段。

如果某个资产没有填写任何档案字段，显示 `未补充档案信息`。详情页的金额、收益、成本和历史变化保持现有逻辑，不读取档案字段参与计算。

## 数据和兼容性

1. 老资产没有 `profile` 时继续正常显示和编辑。
2. 新建或编辑资产时可以提交 `profile`。
3. 后端保存资产时按 `type` 清理 `profile`，只保留当前类型允许的字段。
4. 导入备份时允许 `profile` 缺失。
5. 导入备份时如果 `profile` 存在，必须是对象，且字段值必须是字符串。
6. 导出备份保留 `profile`。
7. schema 版本第一版可以保持 `2`，因为新增字段是向后兼容的可选资产属性。

## 验收标准

1. 资产类型支持可选档案字段。
2. 新增和编辑资产可以填写当前类型的档案字段。
3. 切换资产类型后，保存结果只保留当前类型允许的档案字段。
4. 资产列表展示“标识”列，并按类型显示关键标识。
5. 资产详情页展示类型档案区域。
6. 老数据缺少 `profile` 不会导致页面或导入导出失败。
7. 快照录入、总览汇总、资产走势和收益计算不受档案字段影响。
8. 现有测试通过，并新增资产档案字段相关测试。
