# Univer 收入工作表试点设计

日期：2026-07-12

## 背景

收入管理页目前使用原生 `<table>`、`input` 和 `select` 拼装可编辑表格。它已经支持逐行新增、修改、删除和统一保存，但区域选择、矩形复制粘贴、拖拽填充、键盘导航、撤销重做和批量行操作都需要自行实现。

这些能力属于成熟电子表格内核的职责，不应继续由 RiceFinanceU 重复开发。收入记录又是一行一条、列结构稳定的独立事件，因此最适合作为开源表格组件的第一张试点表。

## 决策

收入表使用 Univer Sheets 开源版替换现有原生表格。

选择 Univer 的原因：

- 开源核心使用 Apache-2.0 许可证。
- 提供区域选择、复制粘贴、拖拽填充、键盘编辑、撤销重做、行操作、排序、筛选和数据校验。
- 支持嵌入 React/Vite 应用。
- 更接近飞书文档、腾讯文档和 Google Sheets 的工作表体验。
- 可以隐藏不需要的功能，把它约束为领域表格，而不是开放式电子表格。

本试点不选择 AG Grid Community，因为区域选择和完整剪贴板能力依赖 Enterprise。RevoGrid 和 react-data-grid 更轻，但要补充整行批量操作、撤销历史或矩形工作表行为，仍会产生较多自研交互代码。

## 目标

1. 用 Univer 提供收入表的电子表格交互内核。
2. 支持矩形区域选择以及与 Excel、Google Sheets 之间的多行多列复制粘贴。
3. 支持拖拽填充、键盘导航、撤销重做、整行复制、批量删除、排序和筛选。
4. 保留“本地批量编辑，点击保存后统一提交”的现有保存模型。
5. 复用现有 `IncomeRecord` 数据模型、领域校验和 Worker/KV 存储。
6. 任意无效单元格阻止整批保存，并定位第一个错误单元格。
7. 服务端对一批收入变更先完整校验，再一次写入，避免部分成功。

## 非目标

1. 不启用公式、图表、透视表或自由单元格格式。
2. 不允许用户新增、删除或重命名业务列。
3. 不实现多人实时协作。
4. 不实现 Excel 文件导入导出；系统剪贴板复制粘贴属于本试点范围。
5. 不把 Univer 工作簿快照作为业务数据保存。
6. 不迁移资产、快照录入或汇率表；收入表验证成功后再分别评估。
7. 不修改收入与资产快照彼此独立的领域边界。

## 产品形态

收入管理页继续使用现有 `TableWorkspace` 作为页面外壳，保留：

- 标题和说明。
- 已保存记录数量。
- 未保存变更数量。
- “保存收入”主操作。
- “放弃修改”次操作。

中间的筛选条和原生 `<table>` 替换为一个受约束的 Univer 工作表。筛选和排序改由工作表自身完成，不再维护页面外部的日期、分类和来源筛选状态。

工作表只暴露五个业务列：

| 列 | 类型 | 规则 |
|---|---|---|
| 发生日期 | 日期文本 | 必填，保存为本地日期 `YYYY-MM-DD` |
| 分类 | 枚举下拉 | 必填，只接受当前 `IncomeCategory` |
| 金额 | 数字 | 必填，必须大于等于 0，保存时四舍五入到两位小数 |
| 来源 | 文本 | 可选，保存前去除首尾空格 |
| 备注 | 文本 | 可选，保存前去除首尾空格 |

表头、列顺序、数据类型和业务校验由系统定义。用户可以调整列宽、排序和筛选，但不能改变表结构。

## 组件边界

### `IncomeSheet`

React 页面组件，负责：

- 创建和销毁 Univer 实例。
- 把收入行和列定义挂载到工作表。
- 暴露保存、放弃修改、未保存数量和定位错误等页面能力。
- 接收 API 加载出的原始 `IncomeRecord[]`。

它不直接拼装 Worker 请求，也不复制收入领域校验。

### `incomeSheetAdapter`

纯适配模块，负责：

- `IncomeRecord[]` 到工作表矩阵的投影。
- 工作表矩阵到收入草稿的解析和规范化。
- 对比原始记录与当前工作表，计算新增、修改和删除集合。
- 返回带行列坐标的校验错误。
- 保持系统记录 ID 与工作表行的稳定关联。

记录 ID 是系统元数据，不作为普通业务列展示或编辑。适配层必须在排序、筛选、复制行和删除行后仍能识别原始记录；复制现有行产生新收入时，不得复用原记录 ID。

### `IncomeManagementPage`

页面负责：

- 加载收入记录。
- 把数据交给 `IncomeSheet`。
- 调用收入批量保存 API。
- 显示页面级加载、失败和成功反馈。

### Worker 批量接口

新增 `POST /api/income-records/batch`，请求包含：

- `creates`：没有既有 ID 的新收入。
- `updates`：既有 ID 和修改后的完整业务字段。
- `deletes`：要删除的既有 ID。

Worker 必须：

1. 读取一次当前数据。
2. 校验请求结构、所有业务字段、更新和删除 ID 是否存在，以及同一 ID 是否出现在冲突操作中。
3. 任意错误时返回 `400` 或 `404`，并且不调用 `writeData`。
4. 全部通过后在内存中应用整批操作。
5. 只调用一次 `writeData`，返回保存后的收入记录或变更摘要。

原有单条收入接口继续保留，避免无关客户端被迫同步迁移。

## 数据流

### 加载

1. 页面通过现有收入查询 API 获取 `IncomeRecord[]`。
2. 适配层生成列定义、业务单元格和稳定的行身份元数据。
3. `IncomeSheet` 创建工作表并记录这一版数据为保存基线。

### 编辑

1. Univer 处理选区、输入、粘贴、填充、排序、筛选和撤销重做。
2. 适配层读取当前业务矩阵，与保存基线比较后计算未保存记录数。
3. 空白行不算新增；任意业务字段出现内容后，该行进入新增草稿。
4. 用户复制既有行时，副本作为新记录处理。
5. 用户删除既有行时，当前矩阵与基线的差异把它识别为待删除；撤销后该差异自然消失。

### 保存

1. 适配层解析当前工作表的全部非空业务行。
2. 统一规范化日期、分类、金额、来源和备注。
3. 若存在错误，停止保存并返回第一个错误的行列坐标；页面聚焦并高亮该单元格。
4. 若校验通过，适配层产生 `creates`、`updates` 和 `deletes`。
5. 页面一次调用批量接口。
6. Worker 全量校验后一次写入 KV。
7. 成功后重新加载服务端数据，重建工作表基线并清空撤销历史和未保存标记。

### 放弃修改

“放弃修改”直接用最近一次成功加载或保存的数据重建工作表。这会清除当前筛选、排序、撤销历史和所有未保存变化。

## 错误处理

- 粘贴超过五个业务列时，只允许映射到从当前选中单元格开始的现有业务列；越界内容不创建新列，并给出明确提示。
- 粘贴超过现有行数时自动增加足够的空白行。
- 日期、分类或金额非法时允许用户继续编辑，但禁止保存。
- 只由过滤结果隐藏的行仍属于当前工作表，保存时不能被误判为删除。
- API 保存失败时保留当前工作表和撤销历史，不重新加载数据。
- 保存进行中禁用再次保存，避免重复批次。
- 页面离开且存在未保存变化时沿用工作区的离开确认机制；若当前没有统一机制，本试点只覆盖收入页浏览器内路由离开提示，不引入云端草稿。

## 样式与约束

- 继续使用紧凑金融工作台视觉，而不是直接暴露 Univer 的完整办公套件工具栏。
- 隐藏公式栏、Sheet 标签管理、任意格式菜单和新增业务列入口。
- 冻结表头，日期和分类列保持可识别。
- 金额显示两位小数并右对齐。
- 公积金分类继续显示受限收入提示，但不改变其保存结构。
- 适配现有明暗主题；Univer 的颜色由应用主题变量驱动。

## 测试策略

### 纯适配层测试

1. `IncomeRecord[]` 正确投影成五列工作表数据。
2. 新增、修改、删除差异计算正确。
3. 排序后的行仍对应正确记录。
4. 复制既有行不会复用原 ID。
5. 空白行不会产生新增请求。
6. 日期、负金额、无效分类返回准确的单元格坐标。

### 页面与组件测试

1. 收入页加载后创建工作表并显示现有记录。
2. 多行矩形粘贴产生多条新增草稿。
3. 拖拽填充和撤销重做更新未保存数量。
4. 批量删除后撤销恢复记录。
5. 过滤隐藏的行不会进入删除集合。
6. 校验失败会定位第一个错误单元格且不调用 API。
7. 保存失败保留草稿，保存成功重建基线。

涉及 Univer Canvas 或浏览器剪贴板、在 jsdom 中不稳定的行为，使用少量浏览器级测试或真实本地浏览器验证，不伪造为只能验证适配层的单元测试。

### Worker 测试

1. 批量新增、修改、删除一次成功。
2. 任意一条非法时整批拒绝且 KV 数据不变。
3. 更新或删除不存在的 ID 时整批拒绝。
4. 同一 ID 出现在更新和删除中时整批拒绝。
5. 成功批次只产生一次完整数据写入。

### 完成验证

```bash
npm run test
npm run build
```

另外使用真实本地应用验证：从 Excel 或 Google Sheets 复制多行数据到收入表，完成编辑、填充、排序、筛选、删除、撤销和统一保存，再刷新确认持久化结果。

## 迁移顺序

1. 添加依赖并建立最小 Univer React 容器。
2. 先实现和测试纯 `incomeSheetAdapter`。
3. 增加 Worker 原子批量接口及测试。
4. 用 `IncomeSheet` 替换收入页原生表格和外部筛选条。
5. 接通未保存数量、保存、放弃和错误定位。
6. 补齐主题样式及浏览器真实交互验证。
7. 试点稳定后，再单独决定是否把相同内核推广到资产、快照录入和汇率。

## 成功标准

用户可以把 Excel 或 Google Sheets 中的多行收入直接粘贴进 RiceFinanceU，使用熟悉的工作表操作批量编辑、填充、排序、筛选和删除，并在一次显式保存后原子写入现有收入数据；RiceFinanceU 不再自行维护选择、剪贴板、填充和撤销等表格基础设施。
