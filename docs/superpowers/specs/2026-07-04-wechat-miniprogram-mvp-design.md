# 微信小程序 MVP 设计

日期：2026-07-04

## 目标

在 `wx-miniprogram/` 下实现 RiceFinanceU 的原生微信小程序第一版。它是现有 PC 前端的移动端客户端，直接调用已经部署好的 Cloudflare Worker API，不新增后端、不改 KV 存储模型。

第一版先做“轻录入版”：登录、总览、资产列表概览、快照录入。它的目标是先跑通个人日常使用链路，而不是一次性复刻 PC 端所有功能。

## 范围

包含：

- 使用邮箱和密码登录 `POST /api/auth/login`。
- 登录成功后把 session token 存入微信本地缓存。
- 总览页读取资产、最新快照、快照列表、汇率。
- 总览页显示总资产、投资类、余额类、投资收益、最近快照和资产概览。
- 快照录入页读取活跃资产和上一次快照值，预填金额。
- 快照录入页提交 `POST /api/snapshots`，让 Worker 继续完成“未填写资产沿用上次值”的逻辑。
- 退出登录时清理本地 token。

不包含：

- 微信登录。
- 多用户。
- 资产新增、编辑、停用。
- 数据导入导出。
- 复杂图表。
- 自动行情或净值同步。

## 技术方案

沿用微信开发者工具生成的原生小程序结构，不引入 Taro、uni-app 或 npm 构建链。小程序代码放在 `wx-miniprogram/`，和现有 React/Web 代码并列。

小程序使用 `wx.request` 调用线上 Worker：

```txt
https://ricefinanceu.ricemarch-finance.workers.dev/api
```

请求封装统一附带：

```txt
Authorization: Bearer <session token>
```

收到 `401` 时清理 token 并跳回登录页。

## 页面设计

页面结构：

- `pages/login/login`：邮箱、密码、登录按钮。
- `pages/index/index`：总览页，也是启动页。无 token 时跳转登录页。
- `pages/entry/entry`：快照录入页。

总览页采用移动端信息流布局：顶部显示总资产，下面是关键指标、资产概览、最近快照。录入页采用卡片列表，每个资产一张轻量录入卡，金额为主，投资类资产额外显示收益和收益率输入。

## 数据流

登录：

1. 用户输入邮箱和密码。
2. 小程序调用 `/auth/login`。
3. Worker 返回 token。
4. 小程序把 token 写入 `wx.setStorageSync('ricefinanceu.sessionToken')`。
5. 跳转总览页。

总览：

1. 并行请求 `/assets`、`/snapshots/latest`、`/snapshots`、`/rates`。
2. 小程序本地计算人民币口径总资产、投资类、余额类、投资收益。
3. 页面展示最近快照和资产概览。

录入：

1. 请求 `/assets` 和 `/snapshots/latest`。
2. 过滤活跃资产。
3. 用最新快照值预填资产金额。
4. 提交被勾选的资产值。
5. Worker 负责合并上一份快照中未提交的资产值。

## 错误处理

- 登录失败展示 Worker 返回的错误信息。
- 网络失败展示“网络请求失败，请稍后重试”。
- 受保护接口返回 `401` 时清理 token 并跳转登录页。
- 快照提交前校验至少选择一个资产，金额必须是非负数字，收益可以为负数，收益率不能小于 `-100%`。

## 测试与验证

自动测试覆盖小程序核心纯函数：

- 汇率换算和总资产汇总。
- 录入页行数据预填。
- 快照提交 payload 生成和基础校验。

手动验证：

- 微信开发者工具可以打开 `wx-miniprogram/`。
- 输入现有 Cloudflare 登录邮箱和密码后能进入总览。
- 总览能读取线上 KV 数据。
- 快照录入能提交到 Worker，刷新 PC 端后可以看到新快照。

## 取舍

第一版不做本地离线缓存和冲突解决。原因是当前数据仍是个人低频使用，Worker 的单 JSON KV 模型已经能覆盖现阶段需求。后续如果小程序成为主力，再补充资产管理、快速新增资产、离线草稿、冲突提示。
