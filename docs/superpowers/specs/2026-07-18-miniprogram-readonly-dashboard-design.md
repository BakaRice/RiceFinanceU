# 小程序只读随身看板设计

## 背景

RiceFinanceU 的 PC 端已经承担资产、快照、收入、汇率和定投等完整维护流程。微信小程序目前仍保留资产编辑、快照录入和 JSON 导入导出，但移动端不会再承担数据维护职责。这些写入能力占据了两个底部导航入口，也让小程序成为体验较弱的 PC 缩小版。

小程序需要重新定位为只读随身看板：用户打开后先确认当前总资产及较上次的变化，再按需查看资产、单项历史和收入情况。所有数据维护继续在 PC 端完成。

## 目标

1. 将小程序改为代码和界面层面的只读客户端。
2. 首页第一屏清楚回答“当前总资产是多少，较上次涨跌多少”。
3. 提供总资产、单项资产和收入的只读趋势。
4. 保留移动端真正适合的搜索、筛选、下钻和下拉刷新体验。
5. 继续使用现有 Cloudflare Worker 数据模型，不创建移动端专属业务模型。

## 非目标

1. 不在小程序中新增或编辑资产、快照、收入、定投或汇率。
2. 不在小程序中导入或导出 JSON。
3. 不把 PC 工作表式交互移植到小程序。
4. 不新增 Worker 持久化结构或写接口。
5. 不提供图表缩放、拖拽或复杂分析能力。
6. 不在本轮展示定投计划详情，也不提供独立汇率页面。

## 产品边界

PC 端是唯一维护入口。小程序只通过读取接口获取同一份资产、快照、快照值、收入和汇率数据，唯一保留的写请求是退出登录时注销服务端会话。

小程序页面中不出现新增、编辑、保存、删除、导入或导出操作。需要维护数据的空状态和说明统一提示“请前往 PC 端维护数据”。

## 信息架构

底部导航由 `总览 / 资产 / 录入 / 数据` 调整为：

1. `总览`：当前总资产、较上次变化、资产趋势、摘要指标和最近变化。
2. `资产`：可搜索、可筛选的只读资产列表。
3. `收入`：收入摘要、月度趋势、分类构成和近期记录。

资产详情是从资产列表和最近变化进入的非 Tab 页面。登录页继续作为未登录入口。退出登录放入页面右上角的轻量菜单，不单独占用一个 Tab。

从 `app.json` 移除录入页和数据管理页注册，并删除对应页面源代码。小程序 API 适配器移除资产、快照和数据导入的写方法，确保只读约束不会因隐藏按钮而失效。

## 总览页

### 第一屏

顶部主卡显示：

- 总资产人民币折算值。
- 最近快照时间。
- 较上一份快照的金额变化。
- 较上一份快照的百分比变化；上一份总额为零时显示 `-`。

上涨、下跌和持平分别使用盈利色、亏损色和中性色。颜色只作为辅助，金额前缀和文字同时表达方向。

主卡下方显示三个摘要指标：投资类、余额类和投资收益。所有金额保持两位小数和千分位；未知值显示 `-`。

### 总资产趋势

趋势图只显示总资产一条折线，使用所有完整快照按汇率折算成人民币后的合计值。用户可选择 `1月 / 6月 / 1年 / 全部`，默认 `6月`。

图表纵轴围绕当前可见数据自动缩放，下界不小于零。只有一个点或所有点相同时仍生成非零范围。触摸数据点时显示日期、实际快照时间和总资产金额。

### 最近变化与收入入口

页面展示最近两份快照之间金额发生变化的前 5 项资产，按人民币变化绝对值从大到小排列。每项显示资产名称、当前金额和变化金额，点击进入资产详情。

首页只展示本月可支配收入摘要和跳转收入页的入口，不重复展示完整收入图表。

## 资产页

资产默认按最近快照的人民币折算金额从高到低排列。页面支持：

- 按资产名称或机构搜索。
- `全部 / 投资 / 余额` 三段筛选。
- 显示正常和暂停录入的资产；暂停资产带只读状态标记。

每行显示资产名称、类型、币种、原币金额和人民币折算值。投资类资产额外显示收益和收益率。没有最近值的资产排在有值资产之后，并显示 `-`。

点击资产行进入详情，不提供行内操作菜单。

## 资产详情页

资产详情显示：

- 资产名称、类型、币种、机构和录入状态。
- 最近金额、人民币折算值、投资收益和收益率。
- 单项资产金额历史趋势，支持 `1月 / 6月 / 1年 / 全部`。
- 该资产允许展示的类型档案字段。
- 最近快照记录，按时间倒序排列。

详情页不显示资产编辑、暂停、恢复、永久删除或定投编辑操作。资产已从最新录入中暂停时，历史数据仍然可见。

## 收入页

收入页顶部以最近有数据的自然月为统计月份，显示：

- 可支配收入：排除公积金等受限类别。
- 总流入。
- 不可支配收入。

收入趋势按自然月聚合，提供 `近6月 / 近1年 / 全部` 范围，默认近 6 月。没有收入的月份在连续范围内显示为 0，避免趋势误读。

分类构成按工资、奖金、副业/额外、投资分红、其他和公积金展示。近期收入记录按发生日期倒序排列，每条显示日期、分类、来源、金额和备注；来源或备注缺失时不占用空白行。

## 图表组件

实现一个小程序原生 Canvas 折线图组件，供总资产趋势、单项资产趋势和收入趋势复用。组件接收已经准备好的展示序列，不承担资产、汇率或收入等领域计算。

组件职责：

- 绘制折线、数据点、横纵轴和必要刻度。
- 根据传入范围绘制纵轴。
- 处理触摸最近点并显示只读浮层。
- 响应容器尺寸变化和范围切换。

组件不依赖第三方图表库，不持有网络状态，也不自行聚合数据。

## 数据与模块边界

### API 适配器

小程序保留以下请求：

- 登录与退出登录。
- 查询资产。
- 查询快照和最近快照。
- 查询全部快照值。
- 查询收入记录。
- 查询汇率。

移除创建快照、创建资产、更新资产、删除资产、导入和导出等客户端方法。

### 纯计算

小程序纯函数负责把 API 数据转换为页面模型：

- 汇率折算和金额格式化。
- 最近两份快照比较。
- 总资产趋势序列和时间范围过滤。
- 单资产趋势序列。
- 资产搜索、分类和排序。
- 收入月度汇总、类别汇总和连续月份补零。

这些规则与 PC 端已有语义保持一致。本轮不同时迁移 PC 端 TypeScript 领域模块，以控制小程序改造范围；新增或镜像的规则必须在小程序测试中覆盖，并在实现计划中记录迁移到 `finance-core` 的后续边界。

### 会话内缓存

小程序在单次运行会话中共享最近成功获取的只读数据。切换 Tab 时可先展示缓存，再在必要时刷新，避免重复白屏。小程序回到前台后刷新数据。

资产、快照值和收入明细不写入本地持久化存储。退出登录时清空 session token 和全部内存缓存。

## 数据流

```text
Cloudflare Worker 读取接口
  -> 小程序 API 适配器
  -> 会话内只读数据仓库
  -> 纯计算函数生成页面模型
  -> 总览 / 资产 / 收入 / 资产详情
  -> Canvas 图表只消费展示序列
```

## 加载、刷新与异常

- 首次进入页面显示骨架或稳定的加载状态，不闪现零金额。
- 页面所需请求并行执行。
- 三个 Tab 均支持下拉刷新。
- 有旧内容时刷新失败，保留旧内容并显示非阻断提示。
- 首次加载失败显示错误状态和重试按钮。
- 接口返回 401 时统一清理会话、内存缓存并跳转登录页。
- 没有快照、资产或收入时使用对应空状态，并提示在 PC 端维护。
- 单个无效快照值或收入记录不导致整页崩溃；纯计算忽略无效项并由测试约束行为。

## 测试策略

### 配置和 API

1. `app.json` 只注册三个只读 Tab，路径与图标正确。
2. 录入页和数据页不再注册。
3. API 适配器包含所需读取接口，不再导出业务写方法。
4. 401 会清理会话并导航登录页。

### 纯函数

1. 最近两份快照的总额、金额变化和百分比计算正确。
2. 外币金额和收益按对应快照展示时使用的当前汇率折算。
3. 趋势范围过滤、排序、单点和无效数据处理正确。
4. 资产搜索、分类、暂停状态和金额排序正确。
5. 可支配、受限和总收入汇总正确。
6. 月度收入聚合会补齐范围内的空月份。

### 页面

1. 总览页覆盖有数据、单快照、无快照、失败、刷新和跳转。
2. 资产页覆盖搜索、筛选、排序、暂停标记和详情跳转。
3. 资产详情覆盖普通资产、投资资产、无历史和无档案。
4. 收入页覆盖汇总、范围切换、空数据和近期记录。
5. 页面中不存在新增、编辑、删除、保存、导入或导出入口。

最终运行：

```bash
npm run mini:test
npm test
```

## 验收标准

1. 小程序底部只有 `总览 / 资产 / 收入` 三个 Tab。
2. 打开首页无需滚动即可看到总资产、最近快照时间和较上次涨跌。
3. 总资产、单项资产和收入趋势在小程序中可查看。
4. 资产可搜索、筛选并进入只读详情。
5. 小程序不再提供任何业务数据写入、删除、导入或导出能力。
6. 空数据和失败状态都引导用户在 PC 维护或重试，不引导小程序录入。
7. 财务明细不持久化到小程序本地缓存。
8. `npm run mini:test` 和 `npm test` 通过。
