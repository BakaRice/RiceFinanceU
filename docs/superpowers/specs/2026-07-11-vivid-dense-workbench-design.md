# 鲜明高密度金融工作台设计

日期：2026-07-11

## 背景

RiceFinanceU 已完成第一轮金融工作台化改造，但全站仍保留通用管理后台的共同骨架：左侧导航体量偏大、页头占用纵向空间、模块经常以同权卡片纵向堆叠。页面已有不少数据，但单位屏幕内能够形成判断的信息仍然不够集中。

本轮不增加功能，也不改变资产快照账本的产品模型。目标是用统一的工作台骨架、更加紧凑的数据布局和鲜明的数字原生色彩，把 PC Web 端升级为具有现代感的个人资产管理工作台。

## 已确认方向

- 以机构资产管理工具的严谨结构为骨架。
- 吸收高端个人财富管理产品的精致与舒适感。
- 密度采用中高档，并向高密度终端方向偏半档。
- 保留固定左侧导航，但收窄为安静的工作台导航轨道。
- 色彩采用浅色数据工作区与高饱和点色结合，并允许品牌区、摘要带和关键数据区域使用受控渐变。
- 总览页中“收入与资产结构”同行，“历史快照与最近变化”同行。
- 后端接口、请求契约、存储结构和领域模型全部保持不变。

## 设计目标

1. 全站进入页面后尽快呈现数据或主要任务，减少标题、说明和容器造成的纵向消耗。
2. 让导航、页头、摘要、工具栏、表格和反馈形成统一的工作台语法。
3. 让鲜明色彩表达品牌、状态、分类和数据关系，而不是装饰页面。
4. 在常见 PC 视口中，第一屏可同时看到页面工作栏、核心摘要和主要数据区。
5. 保持现有业务行为和 API 调用不变，使改造风险集中在前端结构与样式。

## 非目标

- 不修改 Cloudflare Worker 或任何 `/api` 接口。
- 不修改 `Asset`、`Snapshot`、`SnapshotValue`、收入或定投数据结构。
- 不新增行情、交易、自动估值、分析指标或筛选能力。
- 不重做微信小程序。
- 不使用全黑终端风格。
- 不把页面改成大面积渐变、玻璃拟态或 Web3 宣传页。

## 视觉定位：鲜明精密感

专业感来自排版、数字秩序、时间口径和比较关系，不再依靠低饱和灰蓝制造沉稳。页面主体保持清晰安静，关键位置使用高纯度颜色形成数字时代原生的现代感。

### 色彩系统

- 页面底色使用带轻微蓝紫倾向的冷白灰。
- 数据表面使用白色或极浅蓝白色。
- 主色采用明亮电光蓝，承担主按钮、焦点、导航选中和总资产趋势。
- 紫色作为辅助品牌色与收入趋势色。
- 青色用于次级数据或部分资产分类。
- 正向状态使用清晰翡翠绿，负向状态使用珊瑚红，警告使用明亮琥珀色。
- 图表与资产结构使用蓝、紫、青、橙、粉等高辨识度分类色，但同一视区内限制颜色数量。
- 蓝紫渐变只允许用于品牌标记、导航选中微光、总资产摘要强调边和少量关键状态，不作为普通面板背景。

### 色彩约束

- 大金额正文默认仍为深色，正负变化才使用状态色。
- 表格正文不使用多色背景。
- 颜色不能成为唯一状态信号，仍保留正负号、文本和图标。
- 普通边框、禁用状态和说明文字保持中性，避免全页面持续高刺激。
- 所有前景与背景组合满足可读性要求，焦点状态清晰可见。

## 全局工作台骨架

### 左侧导航

- PC 默认宽度控制在约 176–184px。
- 品牌标记使用受控蓝紫渐变，品牌文字缩短纵向占用。
- 导航项高度约 36–38px，图标与文字保持稳定对齐。
- 当前项使用高纯度主色文字、轻量蓝紫背景与左侧强调线。
- 退出登录保留在底部账户区，视觉层级低于业务导航。
- 800px 以下延续窄图标轨道，不增加展开或悬浮逻辑。

### 内容画布

- 常规页面使用流式宽度，最大工作宽度约 1520–1600px。
- PC 页面左右内边距约 20–24px，纵向底部留白约 32px。
- 页面区块间距约 12–16px。
- 普通面板以 1px 边框、4–6px 圆角和表面色差建立层级，不使用阴影。

### 统一页面工作栏

- 用约 52–60px 高的工作栏替代“大标题 + 独立副标题”。
- 左侧显示页面名称，并在同一组内显示时间口径或当前状态。
- 右侧放置唯一主操作与必要次级工具。
- 没有主操作的页面不保留空白操作区。
- 工作栏下方直接进入摘要、表格、图表或表单。

### 密度规则

- 常规正文 13–14px，页面标题约 20px，区块标题约 14–15px。
- 控件高度约 32px。
- 表头高度约 32–34px，常规表格行高约 38–42px。
- 普通面板内边距约 14–16px。
- 金额、比例、日期和数量使用 `tabular-nums`。
- 数字列右对齐，文本列左对齐。
- 空状态优先收缩为面板内提示行，不占据大面积首屏。

## 总览页信息架构

总览页遵循“当前规模 → 趋势 → 构成与流入 → 最近发生的变化”阅读路径。

### 第一层：工作栏与资产摘要

- 工作栏显示“资产总览”、最近快照时间和 `CNY 综合视图`。
- 汇率展示与修改入口并入工作栏的次级工具区，不再独占一整行。
- 摘要带保留总资产、较上次变化、投资类、余额类和投资收益。
- 总资产拥有更强权重，摘要带通过细窄渐变强调边和局部浅色底建立现代感，不做整块高饱和背景。

### 第二层：总资产走势

- 趋势图紧邻摘要带，保持页面最主要的数据模块。
- 周期切换位于模块右上角，控件更加紧凑。
- 总资产使用电光蓝主线，投资类使用青色，余额类使用橙色，收入使用紫色。
- 网格线继续弱化，Tooltip 保留时间口径和精确金额。

### 第三层：收入与资产结构

- 使用一行双栏布局。
- 左侧为收入流入，右侧为资产结构。
- 默认列宽约为 1.15:1；收入信息较多时获得略多空间。
- 收入区保留最近月可支配、总流入、受限流入和主要分类，并保留记录、编辑、管理入口。
- 资产结构使用鲜明但受控的分类色条，显示名称、金额和比例。
- 两块在视觉高度上尽量平衡；内容溢出时内部自然增长，不固定裁切。

### 第四层：历史快照与最近变化

- 使用一行双栏布局。
- 左侧为历史快照，右侧为最近变化。
- 历史快照默认展示最近记录，保留展开详情与删除能力；长列表在该列内继续向下增长。
- 最近变化保留资产、上次金额、本次金额和变化列，变化金额使用鲜明正负色。
- 两块共同表达“发生了什么”，因此置于同一阅读层级。

### 响应式退化

- 1100px 以上保持双栏。
- 1100px 以下允许双栏变为单栏，顺序为收入、资产结构、最近变化、历史快照。
- 表格在需要时横向滚动，不删除关键金额列。

## 其他页面

本轮不重新设计各页面业务流程，但所有 PC 页面共同采用新的色彩、工作栏、内容宽度、面板、表格、按钮和反馈规则。

- 资产管理：资产表格继续作为主工作区，减少页头留白，突出金额与收益列。
- 收入管理：摘要与记录表格更紧凑，紫色作为收入主题辅助色。
- 定投管理：摘要带与计划表格使用统一工作台结构，青色用于计划状态辅助。
- 快照录入：保留资产主数据与时点录入边界，工具栏和录入表格提高密度。
- 资产详情：当前金额和收益保持主层级，资料分区减少卡片堆叠。
- 数据管理与登录：沿用新色彩与控件体系，但保持适合任务的窄内容宽度。

## 前端结构边界

本轮允许抽取或统一以下前端语义结构：

- 工作台导航与内容画布。
- 页面工作栏。
- 摘要带。
- 数据面板与双栏网格。
- 表格、按钮、输入、分段控件和状态标签。

不为了视觉改造引入新的状态管理、组件库或请求层。现有页面继续消费相同 API 数据，数据计算逻辑保持在既有领域函数与页面逻辑中。

## 加载、空状态与错误

- 保留现有加载和错误处理行为，只统一视觉样式。
- 加载状态使用紧凑工作区占位，不跳转到另一套页面骨架。
- 空状态必须明确下一步操作，但不使用大插画或大面积空白。
- API 错误仍通过现有反馈系统显示，不新增后端错误类型。

## 测试与验收

### 自动化验证

- 应用壳测试验证所有导航区域仍可访问。
- 总览页测试验证“收入 + 资产结构”和“历史快照 + 最近变化”的语义分组。
- 现有趋势尺度、收入录入、快照删除和页面行为测试必须继续通过。
- 运行前端测试与生产构建，确认没有 API 或类型变更。

### 本地视觉验证

- 在常见 PC 视口检查左侧导航、工作栏、摘要、趋势和两组双栏。
- 确认第一屏的信息量明显提高，但文字、金额和操作不拥挤。
- 检查鲜明色彩是否集中在品牌、图表、状态和关键操作。
- 检查较窄 PC 视口下双栏退化和表格滚动。
- 检查资产、收入、定投、快照录入、资产详情和数据管理页面是否共享同一工作台气质。

## 完成标准

1. 全站不再呈现“大页头 + 等权卡片”的通用后台骨架。
2. 左侧导航明显收窄，内容区横向利用率提高。
3. 页面密度达到中高偏高，第一屏可看到核心任务区。
4. 色彩比当前版本更鲜明，且没有损害数据可读性。
5. 总览页严格使用“收入 + 资产结构”与“历史快照 + 最近变化”两组双栏。
6. 所有现有 API、数据结构和领域行为保持不变。
7. 前端测试、生产构建和本地页面检查通过。
